## Summary

The CopilotKit integration runs on the **v2 AG-UI protocol** (`@copilotkit/runtime/v2`, `@copilotkit/react-core/v2`), but both `package.json` files pin CopilotKit with a **caret range at `^1.56.3`**. The `/v2` namespace is a preview API surface shipped *inside* the 1.56.x packages. A minor bump within the `^1.56.x` range could move, rename, or remove those `/v2` exports and silently break the chat at install time.

## Where

- `agent-backend/src/routes/copilotkit.routes.js` — imports `@copilotkit/runtime/v2` + `@copilotkit/runtime/v2/express`
- `frontend/src/app/dashboard/agents/[id]/run/page.jsx` — imports `@copilotkit/react-core/v2` (`defineToolCallRenderer`)
- `frontend/src/app/dashboard/agents/builder/page.jsx` — same `/v2` import
- `agent-backend/package.json` → `"@copilotkit/runtime": "^1.56.3"`
- `frontend/package.json` → `"@copilotkit/react-core": "^1.56.3"`, `"@copilotkit/react-ui": "^1.56.3"`

Currently installed = `1.56.3` exactly (verified), so it works today — the risk is purely the open caret range.

## Proposed fix

1. **Pin exact versions** (drop the `^`) on all three `@copilotkit/*` deps in both `package.json` files so a `pnpm install` can't pull a breaking minor that relocates the `/v2` exports:
   - `@copilotkit/runtime`: `1.56.3`
   - `@copilotkit/react-core`: `1.56.3`
   - `@copilotkit/react-ui`: `1.56.3`
2. Re-run `pnpm install` in both `agent-backend/` and `frontend/` to refresh the lockfiles against the pinned versions.
3. Add a short note in each `package.json` / README that the project depends on the **`/v2` preview API** of CopilotKit 1.56.x, and that any version bump must be treated as a **v1→v2 migration**, not a patch bump.

## Acceptance criteria

- [ ] All `@copilotkit/*` deps pinned to exact `1.56.3` in both packages
- [ ] Lockfiles updated and committed
- [ ] Chat still streams text + tool-call events + interrupt/resume on the run page and builder preview
- [ ] A note documents the `/v2` preview-API dependency and upgrade caveat
