**RCP (REST Connector Protocol)** is a standalone, open protocol — not a Persona-specific format —
for exposing REST APIs as AI-callable tools, published as the npm package `rcp-sdk`. An **RCP
Source** in Persona is how you register one: a URL your own backend hosts, plus optional auth,
that Persona discovers tools from live and lets your Agents call.

This is a separate feature from [REST API Tools and REST Tool Sources](/guides/rest-tools) and
from MCP connectors — all three coexist. Reach for RCP specifically when you want your tool
definitions portable to *any* RCP-speaking host, not just Persona.

## How it fits together

1. **Define tools in code** with `defineTool()` from `rcp-sdk/server` — an open, framework-agnostic
   package, not `@personaai/sdk`.
2. **Host them at a URL** — the easiest way is `rcpManifest` on `@personaai/runtime`'s
   `createRuntime()` (or any of the three adapters built on it: Express, NestJS, Next.js), which
   serves your tool list as a conformant manifest at `GET {mountPath}/rcp/manifest`. Any server
   returning the right shape works — `rcp-sdk` itself has zero dependency on Persona.
3. **Register the URL in Studio** — your Project → **RCP Sources** tab → **New RCP Source** — Name,
   Manifest URL, Auth (`none` or `Header`). Choosing **Header** picks or creates a secret from the
   same **Secrets** tab REST API Tools already use.
4. **Test Connection** discovers the manifest right then via `rcp-sdk`'s own client and shows you
   what it found — a read-only preview, refreshed only when you click it again.
5. **Attach the source to an Agent** — same picker as MCP connectors and REST Tool Sources, a new
   "RCP Sources" section on the Agent editor.

<Warning>
  Nothing about a source's tools is copied into Persona's database beyond a display preview.
  **Every Agent turn re-discovers the manifest live**, via `rcp-sdk`'s `createRcpClient()
  .discover()` — there's no "sync" step. A temporarily-unreachable source is skipped for that turn
  (logged, not a hard failure) — the Agent's other tools keep working.
</Warning>

## Defining a tool

```ts
import { defineTool } from 'rcp-sdk/server';
import { z } from 'zod';

const getWeather = defineTool({
  name: 'get_weather',
  description: 'Get current weather information for a city.',
  method: 'GET',
  args: z.object({ city: z.string().describe('City name, e.g. "Paris"') }),
  url: 'https://api.yourapp.com/weather',
  queryParams: { city: (t) => t.arg('city') },
  responseMappings: { temperatureC: '@temperatureC', conditions: '@conditions' },
});
```

See `rcp-sdk`'s own docs (`docs/server.md` in the [RCP repository](https://github.com/hasanraiyan/rcp))
for the full `defineTool()` reference — options, the `t.arg()` helper, and how `args` maps to the
manifest's `params`.

## Hosting the manifest

```ts
import { createRuntime } from '@personaai/runtime';
import { defineTool } from 'rcp-sdk/server';

const runtime = createRuntime({
  baseUrl: process.env.PERSONA_BASE_URL!,
  credential: process.env.PERSONA_CREDENTIAL!,
  resolveUser,
  rcpManifest: {
    tools: [getWeather],
    // Checked against the incoming request's Authorization header — must
    // match the plaintext value of the Secret you pick on the Persona-side
    // RCP Source's Auth tab.
    authToken: process.env.PERSONA_TOOLS_SECRET!,
  },
});
```

See [Static manifest routes](/guides/runtime/routes#rcp-manifest-route-the-same-third-tier-for-the-open-rcp-protocol)
for the exact route this adds and framework-specific notes.

## Identity and auth

RCP's own auth model is `none` / `header` (a static bearer token) — `oauth2` is specified by the
protocol but not yet implemented by any RCP client, Persona included. Unlike REST Tool Sources'
`{{externalUserId}}` template token, an RCP Source passes the current end-user's identity as a
plain HTTP header — `X-Persona-External-User-Id` — attached automatically to every discovery and
tool call when a verified end-user session is behind the call. Your tool's own endpoint reads this
header directly; nothing in your `defineTool()` definition needs to reference it.

## What's not covered yet

- **No SDK method to manage RCP Sources themselves** (create/update/delete/Test Connection) — that
  part is Studio-only for now, same as REST Tool Sources. Tool *definitions* are fully code-first
  via `defineTool()`; registering the *source URL* is a one-time manual step in Studio.
- **`oauth2` auth** — specified by RCP, not implemented by Persona's client yet.
- **Per-tool auth overrides** — a tool declaring different auth than its source's default isn't
  supported yet; register it via a separate RCP Source instead.
