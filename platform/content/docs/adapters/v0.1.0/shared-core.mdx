# Shared Core Internals

Underneath the framework-specific bindings for Express, Next.js, and NestJS sits a shared internal layer (`src/shared/`). This architecture guarantees identical performance, streaming semantics, and security guarantees across all environments.

```
                         └─────────────────────────┘
```

## 1. Streaming Backpressure (`write-node` & `write-web`)

When an agent emits tokens or tool outputs rapidly, a slow network connection between the host server and the client can cause memory buffers to swell.

`@personaai/adapters` implements strict transport backpressure:

### Node.js Streams (`write-node.ts`)
Used by Express and NestJS:
```ts
for await (const chunk of response.body) {
  const canContinue = res.write(chunk);
  if (!canContinue) {
    // Pause reading from upstream until the network buffer drains
    await new Promise<void>((resolve) => res.once('drain', resolve));
  }
}
```

### Web Standards Streams (`write-web.ts`)
Used by Next.js App Router:
- Encapsulates the runtime async generator inside a standard Web `ReadableStream`.
- Respects consumer pull requests (`controller.enqueue()`) so the browser dictates the read pace.

### Socket Disconnect & Cancellation
If a client closes their browser tab or disconnects mid-stream:
1. The socket `close` event triggers an abort signal.
2. The adapter invokes `iterator.return?.()` on the event generator.
3. Network resources are immediately reclaimed without hanging server threads.

## 2. Universal Multipart File Parsing (`multipart-node.ts`)

File uploads (`POST /files` for chat attachments and `POST /knowledge/:id/documents` for vector search RAG) require parsing raw binary bytes alongside text metadata.

The shared multipart parser:
1. **Detects Pre-Parsed Middleware:** If the host application already ran `multer`, the adapter detects `req.file` or `req.files` and converts the buffers directly into `RuntimeUploadedFile` instances.
2. **Native Fallback:** If no multipart middleware exists, the adapter streams the raw request through Node's native Web `Request` and `FormData` parser (built on `undici`), extracting files without requiring external npm dependencies.

---

## 3. Header Redaction & Security (`headers.ts`)

To protect sensitive credentials during debugging and logging, the shared layer automatically sanitizes incoming request headers:

- Sensitive headers (`authorization`, `cookie`, `x-persona-credential`, `x-api-key`) are redacted in structured log outputs.
- Only non-sensitive routing metadata is logged.

---

## 4. Error Sanitization (`errors.ts`)

The shared layer intercepts framework exceptions and ensures responses adhere to Persona’s standard JSON error envelope:

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Missing required agentId in request body"
  }
}
```

- In production (`NODE_ENV === 'production'`), internal stack traces and database details are suppressed.
- In development (`NODE_ENV === 'development'`), verbose error causes and upstream trace IDs are included for debugging.
