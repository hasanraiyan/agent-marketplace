# Capabilities & Admin Surface

By default, `@personaai/runtime` restricts HTTP access exclusively to end-user actions. Project-level resources — LLM API keys, skill definitions, vector search indexes, file stores, and security audit logs — are protected behind an opt-in capability gate.

Every capability flag in `RuntimeCapabilities` defaults to `false`. When a capability is disabled, its routes are not registered in the runtime route table; requests to those endpoints return `404 Not Found` (or `405 Method Not Allowed` if sharing a path with an always-on route) without leaking that the feature exists.

---

## Capabilities Reference

```ts
export interface RuntimeCapabilities {
  /** Full Agent CRUD (create, update, delete) beyond read-only GET /agents. @default false */
  agentsWrite?: boolean;
  /** Full MCP server CRUD + live tool calls and resource reads. @default false */
  mcps?: boolean;
  /** LLM provider configuration — holds sensitive API keys. @default false */
  providers?: boolean;
  /** Custom skill creation and editing. @default false */
  skills?: boolean;
  /** Knowledge base CRUD, document upload, and vector search. @default false */
  knowledge?: boolean;
  /** Project-level file store CRUD and file manipulation. @default false */
  stores?: boolean;
  /** Security and compliance audit log read access. @default false */
  auditLogs?: boolean;
  /** The Architect co-pilot — streams agent-building instructions. @default false */
  architect?: boolean;
  /** Full Workflow CRUD, draft authoring, versions, and Mermaid export. @default false */
  workflowsWrite?: boolean;
}
```

## Recommended Architecture: The Dual-Mount Pattern

In production applications, **do not enable capabilities on the public end-user mount**. If you need an administrative interface (e.g. building an internal developer portal or admin dashboard), instantiate **two separate runtimes**:

1. **Public Consumer Runtime** (`/api/persona`): All capabilities `false`. Authenticated against standard app users.
2. **Admin Runtime** (`/api/admin/persona`): Capabilities enabled. Authenticated against team members or staff roles.

### Production Example

```ts
import { createServer } from 'node:http';
import { createRuntime } from '@personaai/runtime';
import { toNodeHandler } from './node-handler.js';

const baseUrl = process.env.PERSONA_BASE_URL!;
const credential = process.env.PERSONA_CREDENTIAL!;

// 1. End-User Runtime (Safe, zero admin capabilities)
const userRuntime = createRuntime({
  baseUrl,
  credential,
  mountPath: '/api/persona',
  resolveUser: async (req) => {
    // Normal user session auth
    const token = req.headers['authorization'];
    return verifyUserToken(token); // e.g. "usr_12345"
  },
  capabilities: {
    // Everything defaults to false
  },
});

// 2. Admin Runtime (Privileged team surface)
const adminRuntime = createRuntime({
  baseUrl,
  credential,
  mountPath: '/api/admin/persona',
  resolveUser: async (req) => {
    // Strict role check: must be staff/admin
    const token = req.headers['authorization'];
    const user = await verifyAdminToken(token);
    if (!user || user.role !== 'platform_admin') {
      return null; // Triggers 401
    }
    return user.id;
  },
  capabilities: {
    agentsWrite: true,
    skills: true,
    knowledge: true,
    stores: true,
    auditLogs: true,
    architect: true,
    // mcps: true,
    // providers: true, // Only enable if allowing key management via HTTP
  },
});

// 3. Dispatch based on request path
const userHandler = toNodeHandler(userRuntime);
const adminHandler = toNodeHandler(adminRuntime);

const server = createServer(async (req, res) => {
  if (req.url?.startsWith('/api/admin/persona')) {
    await adminHandler(req, res);
  } else if (req.url?.startsWith('/api/persona')) {
    await userHandler(req, res);
  } else {
    res.writeHead(404).end();
  }
});

server.listen(3210);
```

## Security Best Practices

1. **Protect `providers`:** The `providers` capability allows reading and updating LLM provider credentials and API keys. We recommend managing providers programmatically using [`@personaai/sdk`](/docs/sdk/v0.7.5/resources/providers) directly in backend worker scripts rather than exposing HTTP endpoints.
2. **Coarse-Grained Authorization:** Capability flags are binary per mount. If you need fine-grained permissions (such as allowing team members to update knowledge bases but not delete them), perform authorization inside `resolveUser` or use a custom framework middleware ahead of the runtime.
3. **Auditing:** Combine `auditLogs: true` with [Lifecycle Hooks](/docs/runtime/v0.10.0/guides/hooks) (`beforeToolCall`, `afterToolCall`) to maintain complete compliance trails.
